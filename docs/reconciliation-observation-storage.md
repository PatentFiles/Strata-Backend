# Prospective bounded reconciliation observations

`RECONCILIATION_SUMMARY_V1` replaces only new RECONCILIATION observation payloads. It is explicitly **not replayable full exchange evidence**. Full signed snapshots remain in memory for every ledger/identity/history/position/cash/fill/settlement check. Account reconciled_at and evidence_digest still bind the full snapshot; observation.digest instead binds the summary, which carries fullSnapshotDigest. Financial events retain their existing deduplicated records. No old row deletion/backfill, cadence change, pagination change, or migration.

Source consumer inventory: ledger is the only RECONCILIATION writer; no repository runtime reader selects its payload arrays. Personal activation and release/fee/recovery readers select separate named kinds (not RECONCILIATION). SQL strata_v13_capture_transport returns immediately for this kind. Freshness/authority readers use account.reconciled_at/evidence_digest and live signed snapshots, not stored RECONCILIATION arrays. External ad-hoc monitoring must branch on version: counts and fullSnapshotDigest are available, missing arrays are intentional, never empty-account evidence. Historical rows remain old full shape.

Summary keeps scope (key fingerprint hashed), times/coverage flags/cash, exact historical counts, nonterminal-order/nonzero-position counts, and at most eight exposure samples with bounded strings and explicit omittedCount. Full-state and exposure digests commit to omitted data but do not make it retrievable. Sample oversize fields become null rather than truncated identities. No request/credential/cursor/raw provider payload is stored in this new receipt.

Four pure tests cover digest lineage, nonmutation, historical growth, bounded exposure and omissions. One actual PostgreSQL acceptance proves persisted summary digest versus unchanged full account digest/timestamp; all 80 prior acceptance tests remain green. This removes history-proportional observation payload growth, not all database growth: one compact observation per tick remains, as do financial events and existing intent updates. Retention/checkpoints remain separate reviewed future work.
