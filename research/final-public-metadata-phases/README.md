# Two distinct public-only final-stage overlap scopes — LOCAL prototype

Default OFF, independently controlled by exact `STRATA_FINAL_PUBLIC_METADATA_PREFETCH_ENABLED=true`. The existing PREPARE flag does not enable these phases. No environment or production setting was changed.

A (`FINAL_MARKET`) starts after loading an exact PREPARED entry during dispatch claim, overlaps the existing claim/prechecks, and is consumed once by that intent's final market reader. The signed book and current fee review still run at their original boundaries. B (`WIRE_FEE`) is a newly captured invocation started before final signed account work and consumed once only by the guarded wire fee verifier, AFTER its existing standing/account fences. A is never reused for B. Neither phase stores fee approvals, signed account data, signed book data, order permission, or extends source/capture clocks.

Both use the existing shared coordinator's three advisory request slots, two account slots, 32 failure/attempt tombstones, original source-derived deadline, bounded response bodies and cancellation settlement. An earlier consumed phase is discarded only after its capture was materialized; if resources have not actually settled, the next phase declines and the original fresh path remains. Started failed/cancelled attempts retain consumer failure and cannot silently retry through fresh fallback. Per-dispatch invocation identity prevents a concurrent no-op replay cancelling another dispatch's attempt. STOP discards advisory work; its tombstone remains until the owning dispatch finishes.

Successful actual owned-ledger/reader/wire-probe fixture executes 15 public calls total: five PREPARE, five distinct FINAL, five distinct WIRE, with the same signed book/snapshot and authority queries/clock calls as disabled. This count is established for the tested complete exact-market schema; malformed/429 paths are separately fail-closed and do not launch replacement attempts. Later gate failure can waste up to five newly started advisory calls per phase (ten per invocation), while sharing the existing request limits. This is a tradeoff, not free work.

Existing concurrent final-market gather retains first-observed-error semantics. Enabled overlap can change which simultaneous public/private failure is logged first; it does not make authority, reserve/recovery or POST outcomes more permissive. Explicit checkpoint order remains: final gates before final-market consumer; wire standing/account fences before wire metadata consumption; unchanged synchronous source/quote guards before raw HTTP. No artificial delay is used to force diagnostic-label parity.

Fixtures run the real ProductionExecutor, OwnedAccountLedger, final market reader, public probe, signed account interface and guarded raw-wire clock with actual disposable PostgreSQL. Provider responses and private fee authorization ports are explicit test doubles, not authenticated production approvals or fills. Controlled elapsed delays demonstrate actual overlap; they are not a reconstruction of an unmeasured historical wire probe. Source/evidence ages, request shape and cash-model fingerprints are compared. A separate budget sweep labels the unknown wire public share rather than asserting the entire downstream stage is removable.

No migration, live order, rollout approval, automatic activation, guaranteed fill or profitability claim. Independent review and final combined PostgreSQL16/17 suites remain required before publication.

## Controlled timing experiment (not a historical replay)
The paired disposable-PG fixture injects real asynchronous request delays: each ledger request 16 ms, public root requests 50 ms and dependent event requests 150 ms, final signed account interface 300 ms, and each fee remainder 40 ms. A monotonic elapsed clock plus an explicitly assumed 3650 ms pre-dispatch elapsed input and original 228 ms BTC-provider age is used; no capture timestamp is rewritten. The source/model/request is identical in both arms. The enabled arm must reach the actual raw-wire guard with at least 200 ms remaining; the disabled arm must refuse without POST. Timelines prove A starts before ledger request waits and is consumed later, and B starts before signed account work and is consumed afterward. Capture manifests report their own original request/ready times, not decision-time books.

One local run observed disabled dispatch 1292 ms/refused versus enabled 850 ms/mock wire effective age 4705 ms. These are machine-dependent controlled measurements, not measured production savings, authenticated exchange acknowledgment, fill or profit. The historical downstream wire-probe share remains unknown and is swept separately; no hypothetical public/private split is asserted as an observation. Failure fixtures compare financial cash/reserve accounting as well as no-POST and terminal refusal. Private lease/grant ports are read-only test doubles here, not a complete production consent integration.
