# STOP-held owner signed diagnostic

Extends the existing owner/AAL2 protected `/release/my-signed-exchange-proof` read-only action. A commissioned approved MAIN account can be inspected while STOPPED (released worker, ARM false), without KILL or a backend restart. Saved execution_enabled need not be false. Existing legitimate KILL/no-worker onboarding remains supported.

Initial and final queries pin account, policy, worker lease, restricted credential, financial-account and provider-connection row versions plus lease fence/holder and signer identity. Final query runs after all signed exchange, fee and readiness awaits, checks held state, no positions/reservations/nonterminal or UNKNOWN operations, and rejects any binding/revision drift. ARM→DISARM does not advance the existing fencing token; request-local xmin equality detects that ABA. Tokens are not durable authorization, exposed secrets or order authority. No locks span network; no SQL writes or schema migration.

The 45-second existing signed-read lifetime is rechecked after all awaits. An unsuccessful final guard reports signedExchangeReadAttempted=true but authenticatedExchangeFlat=false, never implies the read was not attempted. Current endpoint owner/MFA middleware is unchanged; no browser account selector, grant issuance, reconciliation writes, automatic START or order POST is added. A successful result is point-in-time evidence only and still has tradingAuthorized=false/liveEligible=false/recordPersisted=false. START retains its own independent transactional gates.

- Actual endpoint with two independent disposable PG clients: unchanged STOP, ARM, two separately committed ARM→DISARM updates with same fence, fencing change, revoke→reinstate, credential change, financial/provider/account revisions, exposure and uncertain reservation insertion, final readiness mutation, total45s expiry, KILL no-worker, absent-worker creation race, unsafe killed active worker. No runtime write SQL permitted by test wrapper.
- Run API `node scripts/run-v13-disposable-postgres.mjs src/lib/strata/ownerSignedExchangeReleaseProof.postgres.test.ts`; it creates and destroys isolated PG only. Fixture signer/exchange responses are synthetic and make no production requests.

No production deployment or new authority is implied by local tests. CI wiring/full combined validation is owned by the integrator. No database migration required. Existing provider cooldown/request budget and first-read-failure behavior remain unchanged; this does not promise unlimited repeated diagnostics without rate limiting.

Query-pressure review: the new snapshot is LIMIT2, exact owner/account joins, scalar revisions only; it never aggregates approval/observation/order history. Current position predicate uses quantity>0, equivalent under existing nonnegative quantity CHECK and eligible for existing partial owned-position index. Current emergency reservations match the existing unresolved-state partial index. Intent safety predicate uses the existing account-leading evaluation index; it may inspect that account's intents but not a global history aggregation. The preexisting separate request-history query remains unchanged because signed snapshot mapping uses it; this endpoint is not claimed history-free. Disposable PG EXPLAIN with local enable_seqscan=off verifies index eligibility, not measured production performance. No index/schema migration added.
